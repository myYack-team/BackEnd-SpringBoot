# 관리자 서버 로그 조회

관리자 `/api/admin/logs`는 Logback이 기록하는 회전 파일을 Java 파일 API로 읽는다. OS 명령 실행이나 Java의 자식 프로세스 생성에 의존하지 않으므로, 실행 중 JDK 패키지가 교체되어도 같은 원인으로 로그 조회가 실패하지 않는다.

- 기본 파일: `${user.home}/.myyak/logs/application.log`. 변경 시 Spring Boot의 `logging.file.name`을 사용한다. 로그 경로는 API 입력으로 받지 않는다.
- 콘솔 출력도 유지한다. 기존 journald 로그와 별도 자동 장애 수집기는 계속 사용할 수 있다.
- 10 MB 또는 날짜 변경 시 gzip 회전, 지난 날짜 7개 보관, 보관 파일 용량 상한 100 MB. 현재 파일은 별도로 최대 크기를 적용한다. 단일 이벤트가 크면 순간적으로 초과할 수 있다.
- 배포 workflow가 기본 로그 디렉터리를 소유자 전용으로 만든다. 파일 경로를 변경하면 해당 디렉터리의 접근 권한도 별도로 설정해야 한다.
- 시간 범위는 1~168시간, 기본 24시간이다. 읽기 요청 하나는 최대 16 Mi 문자, 한 줄 64 Ki 문자, 범위 내 이벤트 10,000개로 제한한다. 초과하면 `LOG413`을 반환하며 조회 시간을 줄여야 한다.
- 파일이 없거나 읽을 수 없거나 압축 파일이 손상되면 HTTP 503/`LOG503`을 반환한다. 정상적인 빈 결과와 조회 실패를 구분한다.
- 현재·압축 로그를 읽고 시간/레벨 필터, 스택과 관련 로그 묶기, 중복 접기, 최신순 페이지 처리를 적용한다. 파일 회전과 신규 기록은 동시에 일어날 수 있어 요청마다 완전히 같은 스냅샷을 보장하지 않는다.

새 파일에는 적용 후의 로그부터 기록된다. 배포 이전 로그는 journald에 남아 있으며 자동으로 파일에 복사하지 않는다. 이 변경은 Gemini CLI의 턴 제한이나 자동 분석 보고서의 분류를 변경하지 않는다.

검증은 임시 디렉터리의 합성 로그로 수행하며 운영 DB와 외부 모델을 사용하지 않는다. 실제 배포 시 파일 생성과 관리자 세션을 통한 조회를 확인한다.
